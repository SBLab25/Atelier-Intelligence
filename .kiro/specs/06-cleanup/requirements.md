## 2. Decisions (defaults; confirm or change before implementation)
| ID | Question | Default | Alternatives considered |
|---|---|---|---|
| OD-34 | Stale scripts and logs | **Delete** the ad hoc scripts and logs listed in design §1 (all tracked, so `git checkout HEAD -- <file>` restores them; copies also go to `evidence/removed/`). Add a root `.gitignore` for `*.log` and `main_log*.txt`. **Delete `dashboard2.py`** (random-data mock; its style is in `dashboard.py`). **Keep** `generate_diverse.py` (a data generator a user may run; documented in README with its side effect), `create_zip.py` and `Team_Contribution_Scripts.zip` (team workflow artifacts, not code paths). | Move everything to `archive/`: keeps clutter and the Supabase-altering script runnable. Keep all: fails R-11. |
| OD-35 | Dashboard upload / `ingest_json` overwrite (F-09) | **Append by default; replace only on explicit request.** Append stays idempotent on `event_id`. CLI: `--append` kept (accepted, now the default), new `--replace`. Dashboard: the checkbox becomes "Replace all rows in tracking_events" (unchecked) with a warning. Messages name the real destination (`PostgreSQL tracking_events`), not the Parquet path. Replace stays available: no functionality removed. | Keep replace as default with a warning: one unchecked box still deletes the live table. Route through the repository: changes what the dashboard reads (out of scope). |
| OD-36 | Broad-catch policy | **Narrow where the failure set is known; keep documented boundaries.** Known sets: database (`SQLAlchemyError`, pandas `DatabaseError`), files (`OSError`), JSON (`json.JSONDecodeError`/`ValueError`), HTTP (`requests.RequestException`), LLM response shape (`KeyError`, `IndexError`, `ValueError`, `TypeError`). Boundaries keep `except Exception` with `# broad-except: <reason>`, log with `exc_info`, and return a structured error: LangGraph workers, `ingestion_worker`, MCP client connect/call, ChromaDB calls, repository error conversion. The collector per-row insert (F-07) is annotated and left to Spec 07. An AST test enforces the policy. | Narrow everything: unknown failure sets in SDKs would crash tools instead of degrading. Leave as is: fails R-10. |
| OD-37 | `sys.path.insert` | **Remove the redundant and wrong ones** (`dashboard.py`, `guardrails/output_validator.py`, `generate_diverse.py`, 5 test files). **Keep script-entry ones** with a comment pointing at Spec 11 (R-14). | Remove all and require `python -m`: breaks documented commands; packaging belongs to Spec 11. |
| OD-38 | Historical documents | **README.md is rewritten where wrong** to match the code and the gate's commands. `Project_Memory.md`, `Project_status.md`, `docs/development_status.md` get a **Superseded** banner. `docs/1–13` and `Project Details/*` get a **Historical design reference** banner. A new `docs/README.md` indexes every document, its status, and the known divergences. Bodies of historical documents stay unchanged. | Rewrite every document: weeks of work and loses design history. Delete them: loses intent the later Specs still use. |

## 3. Requirements
| ID | Requirement | Intended behaviour change |

| CL-04 | No handler in app code SHALL consist only of `pass`/`...`/`continue` without a reason comment. | Silent failures surface |
| CL-05 | Every remaining `except Exception`/`BaseException`/bare `except` in app code SHALL carry `# broad-except: <reason>` and either re-raise, return a structured error, or log with `exc_info`. Enforced by an AST test. | — |
| CL-06 | Narrowed handlers per OD-36. Unexpected exceptions SHALL propagate to the next boundary instead of being swallowed. | Some failures now raise or exit non-zero |
| CL-07 | CLI (`main.py`): console output SHALL not fail or be dropped on non-UTF-8 consoles (stream reconfigured with `errors="replace"`); failure to read the final state or save `last_run.json` SHALL print `[ERROR] <where>: <Type>: <message>` to stderr and exit 1. | Exit 1 where it was 0 with lost state |
| CL-08 | Dashboard: database loaders SHALL catch only database errors and report them in one visible warning that names the panel and error type (credentials stripped); file, JSON and launch errors are handled by type; unexpected errors reach Streamlit's error display. | Empty panels now explain why |
| CL-09 | Collector: `POST /admin/api-keys` database failure SHALL return 500 `Database error` without the driver text (logged server-side); unconfigured database SHALL return 503; keep-alive catches only `requests.RequestException`. | No internals in responses |
| CL-10 | `ingest_json` / dashboard upload per OD-35; a JSON parse failure SHALL raise with the file and cause instead of reporting "no records"; the existing-ids read SHALL treat only a missing table as empty. `ingest_json()` wrapper removed (no callers). | Default append; explicit replace |
| CL-11 | `sys.path.insert` per OD-37; each remaining one carries a `Spec 11 (R-14)` comment; a test lists the allowed files. | — |
| CL-12 | Stale scripts and logs per OD-34; `requirements.txt` per OD-40. | Files removed |
| CL-13 | Documentation per OD-38/OD-39. A test SHALL check README against the code: `main.py` flags, collector routes, environment variables (settings `KNOWN_KEYS`), ports (service registry), referenced repository paths, and banners on historical documents. | — |
| CL-14 | Startup smoke checks SHALL cover: MCP servers start and listen; demo pipeline; ingest probe; mode mismatch (Spec 05 gate); dashboard renders headless (`streamlit.testing.v1.AppTest`) with the database unreachable and shows the warning instead of failing; `main.py --help`, `run_servers.py --help`, `tools/ingest_json.py --help`, `python -m settings`. | — |
